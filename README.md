# Cyclone C

The Cyclone runtime in C99, written from the specification: framing, the schema
handshake, heartbeat, and a non-blocking TCP/UDP tick loop.

No dependency. No threads. No async runtime. A C99 compiler and `make`.

```sh
make          # build build/libcyclone.a
make test     # build and run every test
make sanitize # every test again under ASan + UBSan
make examples # build the runnable echo server and client
```

## What this is, and what it answers to

The [protocol specification](https://github.com/cyclone-protocol/protocol-specification)
is the authority here, and nothing else is:

| Document | What it fixes |
|---|---|
| RFC-0001 | What Cyclone is, and the five design decisions behind it |
| RFC-0002 | The byte layout: primitives, string, bytes, model, array, enum, version differences |
| RFC-0003 | Conformance: the test vectors an implementation must pass, all of them |
| [Implementation guide](https://github.com/cyclone-protocol/protocol-implementation-guide) | The layer above: framing, handshake, heartbeat, the transport contract |

Where this library and any other Cyclone SDK disagree, the RFCs decide, and both
sides agreeing with each other proves nothing.

Three layers, and this library is one of them:

```
  your application
        |
  codec         RFC-0002 - Model <-> bytes                  generated by cyclonec,
                                                            NOT in this repository
        |
  runtime       implementation guide - frames, handshake,   src/frame.c, src/session.c,
  (this repo)   heartbeat, tick loop, events                src/core.c, src/server.c
        |
  transport     TCP or UDP, or one you write yourself       src/transport/
```

A message payload is opaque here, from the socket all the way up to the event
handed to your application. Nothing in this repository reads a byte of it.

## Quick start

### Client

```c
#include "cyclone/net.h"

cyc_transport transport;
cyc_connection *connection;

if (cyc_tcp_connect("127.0.0.1", 9321, &transport) != CYC_OK) {
    return 1;
}
connection = cyc_connection_create(transport, demo_schema(), NULL, cyc_now_ms());

for (;;) {
    const cyc_event *events;
    size_t count = cyc_connection_tick(connection, cyc_now_ms());
    size_t index;

    events = cyc_connection_events(connection, &count);
    for (index = 0; index < count; ++index) {
        switch (events[index].kind) {
        case CYC_EVENT_READY:
            /* only now may you send */
            break;
        case CYC_EVENT_MESSAGE:
            handle(events[index].message_id, events[index].payload, events[index].payload_len);
            break;
        case CYC_EVENT_DISCONNECTED:
            return 0;
        default:
            break;
        }
    }
}
```

### Server

```c
cyc_listener listener;
cyc_server *server;

cyc_tcp_listen("127.0.0.1", 9321, &listener);
server = cyc_server_create(listener, demo_schema(), NULL);

for (;;) {
    const cyc_event *events;
    size_t count = cyc_server_tick(server, cyc_now_ms());
    size_t index;

    events = cyc_server_events(server, &count);
    for (index = 0; index < count; ++index) {
        if (events[index].kind == CYC_EVENT_MESSAGE) {
            handle(events[index].peer, events[index].message_id, events[index].payload,
                   events[index].payload_len);
        }
    }
}
```

`examples/echo_server.c` and `examples/echo_client.c` are two runnable processes
doing exactly this. Start the server first:

```sh
make examples
./build/examples/echo_server
./build/examples/echo_client
```

### Who owns what

- `cyc_connection` and `cyc_server` are opaque handles: `_create` allocates,
  `_destroy` frees. Everything else they need is allocated once at creation.
- A `cyc_transport` handed to `cyc_connection_create` is **owned by it** from
  that moment: `_destroy` calls the transport's `close_hard`, which frees it. The
  same holds for a `cyc_listener` handed to `cyc_server_create`, and for every
  peer transport the listener accepts.
- The `cyc_schema` you pass is **borrowed**, not copied. It must outlive the
  connection or server - a `static` one, as `examples/demo/src/schema.h` builds,
  is the simple answer.
- `cyc_event.payload` points into the connection's own buffer and is valid until
  the next tick on that same connection. Keep it longer by copying it.

## Where the codec is

It is not here, and that is deliberate.

`cyclonec` generates the RFC-0002 codec runtime - `CycloneWriter`,
`CycloneReader`, `CycloneDecodeError`, `CycloneLimits` - into your own project,
together with a codec per message and the fingerprints below. There is exactly
one implementation of RFC-0002 in C, it lives in the generator, and its
conformance is proved there against the committed cross-SDK vectors.

A second copy in this library would be a second implementation of RFC-0002 in
the same language. Two encoders drift, and RFC-0001 §6.1 is explicit that the
drift is silent - both ends still decode, the bytes just stop matching. So this
library carries none.

What it does ship is `include/cyclone.h`: the three markers `CYCLONE_MODEL`,
`CYCLONE_FIELD(type)` and `CYCLONE_CODEC(...)` that `cyclonec` reads out of your
sources. They expand to nothing, so an annotated model compiles on any C or C++
toolchain whether or not `cyclonec` has ever run over it.

What you hand this library instead is two things `cyclonec` also generates:

- **the message id**, for `cyc_connection_send` and for `cyc_event.message_id`;
- **the schema table** - `CYCLONE_SCHEMA_FINGERPRINT`, and per message its id,
  its fingerprint and its prefix chain - which becomes a `cyc_schema` and is what
  the handshake compares.

```c
for (index = 0; index < CYCLONE_MESSAGES_COUNT; ++index) {
    DEMO_MESSAGES[index].id = CYCLONE_MESSAGES[index].id;
    DEMO_MESSAGES[index].fingerprint = CYCLONE_MESSAGES[index].fingerprint;
    DEMO_MESSAGES[index].prefixes = CYCLONE_MESSAGES[index].prefixes;
    DEMO_MESSAGES[index].prefix_count = CYCLONE_MESSAGES[index].prefix_count;
}
```

Encoding is then your generated codec's job, and this library only ever sees the
bytes it produced:

```c
CycloneWriter writer;
cyclone_writer_init(&writer);
GameMessageStateCodec_encode(&writer, &state);
cyc_connection_send(connection, GAME_MESSAGE_STATE_MESSAGE_ID, writer.data, writer.len);
cyclone_writer_free(&writer);
```

### The demo project

`examples/demo/` is that whole path, committed and real rather than described:

```
examples/demo/
  cyclone.toml                  src = "src/models", out = "src/generated"
  src/models/game.h             the models you annotate - the only file written by hand
  src/schema.h                  CYCLONE_MESSAGES -> cyc_schema, the loop above
  src/generated/                what `cyclonec generate` wrote, committed as-is
    runtime.h                     CycloneWriter, CycloneReader, limits, errors
    handshake.h                   fingerprints, prefix chains, message ids
    game_message_state.h          one file per model per codec
    player_input_input.h
    vector3_state.h
    vector3_input.h
    *_cyclone.h                   the per-model free helpers
  .cyclone/schema.json          the build-time record cyclonec compares against
```

The models mirror RFC-0002 §15's worked example - a `u32`, a `string`, a nested
`Vector3` of three `f32`, another `u32` and a `bool` - plus a `PlayerInput` going
the other way. `GameMessage.last_seen_at` is deliberately *not* annotated: it is
a field of your struct that no codec carries, and `tests/test_demo.c` asserts it
arrives as `0` on the far side. Your types stay yours (RFC-0001 §6.6).

Regenerate after editing a model, from that directory:

```sh
cyclonec generate
```

No CI job here checks that tree for freshness. Doing so would mean installing a
generator from outside this repository, and this repository builds on its own.

## Wire format

Every byte this library puts on a transport is a frame, and every frame starts
with a type byte.

```
  0  DATA        11-byte header, then the payload
  1  PROBE       one byte, no body
  2  ACK         one byte, no body
  3  HANDSHAKE   5-byte header, then an opaque payload
```

### Data frame

```
  +----+----+----+---------------+---------------+---------------------+
  | 00 | 43 | 59 | message id    | payload len   | payload             |
  |    |'C' |'Y' | 4B u32 LE     | 4B u32 LE     | = payload len       |
  +----+----+----+---------------+---------------+---------------------+
   ^0    ^1   ^2      ^3-6            ^7-10           ^11..
```

The message id is a message *type*, assigned by your schema. It is not a
sequence number, and nothing here reorders, retransmits or deduplicates.

### Handshake frame

```
  +----+---------------+----------------------------+
  | 03 | payload len   | handshake payload          |
  |    | 4B u32 LE     | = payload len              |
  +----+---------------+----------------------------+
```

### Framing on a byte stream vs. a packet

On a stream, frames sit back to back with no separator, and `cyc_stream_decoder`
works incrementally - feed it one byte at a time if that is what arrives. **Any
framing violation on a stream is fatal**: there is no resynchronisation point, so
the decoder is poisoned permanently and the session closes.

On a packet transport, one packet holds exactly one frame - a short packet or a
packet with bytes left over is broken. **A framing violation there is not
fatal**: drop that packet and carry on, because a single datagram cannot corrupt
shared parsing state. The asymmetry is deliberate.

## The handshake

The client sends one hello. The server is the only side that compares anything,
and it answers with a single verdict byte. The usual case is one round; exactly
one case needs a second.

```
  CLIENT                                         SERVER
    |  -- HANDSHAKE(hello) ---------------------> |
    |                                             |  1. frame check
    |                                             |  2. version check
    |                                             |  3. fingerprint check
    |  <-- HANDSHAKE(verdict, 1 byte) ----------- |  decided
    |  <-- HANDSHAKE(4 = need more, list) ------- |  undecidable
    |  -- HANDSHAKE(prefix answers) ------------> |
    |  <-- HANDSHAKE(verdict, 1 byte) ----------- |
```

### Hello payload

```
  protocol version   4B u32 LE   always 2
  schema fingerprint 8B u64 LE
  message count      4B u32 LE
  then one 14-byte entry per message:
      message id     4B u32 LE
      field count n  2B u16 LE
      fingerprint    8B u64 LE   the message's own, i.e. prefix n
  length == 16 + 14 * count, exactly
```

### Verdict byte

| Byte | Meaning |
|---|---|
| 0 | accepted |
| 1 | wrong handshake version - the hello layout itself differs |
| 2 | schema conflict - a message both sides know puts different fields at a shared index |
| 3 | malformed hello |
| 4 | not a verdict: a request for more information, and it never ends the session |
| >=5 | broken |

### How the server decides

The schema fingerprints matching ends it: accepted, without reading a single
entry. Otherwise, for each message id **both** sides declare, with `n_c` the
client's field count and `n_s` the server's:

| | Condition | Result |
|---|---|---|
| a | the two message fingerprints are equal | identical, move on |
| b | `n_c == n_s`, fingerprints differ | verdict 2 |
| c | `n_c < n_s` | compare the client's fingerprint with the server's prefix at `n_c` - equal moves on, otherwise verdict 2 |
| d | `n_c > n_s`, `n_s > 0` | undecidable: ask for the client's prefix at `n_s` |
| d | `n_c > n_s`, `n_s == 0` | the empty prefix is a prefix of everything, move on |

That is RFC-0002 §9.1's prefix test written out in bytes: comparing at
`k = min(n_c, n_s)` asks exactly whether the shorter field list is an exact
prefix of the longer one.

**Different schemas are still accepted.** The condition is not "identical", it
is "wherever the two overlap, they agree". A peer that knows messages the other
does not, or carries extra fields at the end of a shared message, connects
normally - RFC-0002 §9.1 *requires* those peers to interoperate. Only two
different fields at the same index inside the shared part are refused, and one
such message refuses the whole session.

Three rules keep the exchange bounded: at most one query per session; a client
that receives a second query treats the session as broken; and the client's
handshake deadline covers the whole exchange and is **not** reset by the extra
round.

### Timers, and why the two roles differ

| Field of `cyc_config` | Default | Meaning |
|---|---|---|
| `handshake_timeout_ms` | 5000 | client: a hard deadline on the whole handshake. server: the silence window while a peer has not finished |
| `heartbeat_interval_ms` | 5000 | how long a peer may be silent before it is probed |
| `heartbeat_timeout_ms` | 15000 | how long a probe may go unanswered before the peer is declared dead |
| `max_frames_per_tick` | 64 | tick fairness; the rest arrives next tick |
| `max_message_bytes` | 65536 | the largest payload this side sends or accepts |
| `max_peers` | 256 | server only |

A client mid-handshake has no heartbeat at all - it has a hard deadline and is
waiting for exactly one thing. A server does have one for every peer, because it
must tell "still computing" from "vanished". A client that answers probes without
ever sending a valid hello can hold a server slot indefinitely: that is the
specified behaviour, and no implementation may invent an absolute cap.

## Heartbeat

Probe **on silence**, never on a timer:

```
  NORMAL  --- silent for heartbeat_interval ---> send exactly one PROBE
     ^                                                |
     |                                            PROBING
     |                                                |
     +--- any valid frame arrives ---------------- unanswered for
          (DATA, PROBE, ACK, HANDSHAKE)             heartbeat_timeout
                                                        |
                                                        v
                                                   peer declared dead
```

Two consequences: a peer with traffic flowing is never probed at all, and nobody
is ever cut off without being probed first. Worst-case detection is
`heartbeat_interval + heartbeat_timeout`, 20 seconds by default. An ACK is sent
from inside the tick, whether or not the application ever looks at the event.

## The tick

One tick does four things, in this order, and the order is not negotiable:

```
  0. the CONNECTED event, once in a session's life
  1. push out whatever is still stuck   <- before anything else: wire order is absolute
  2. drain arriving frames, up to max_frames_per_tick
  3. run the protocol clocks            <- handshake deadline, probe, declare dead
  4. hand the event list to the application
```

Nothing blocks. Nothing sleeps. Nothing spawns a thread. `cyc_connection_tick`
takes the timestamp as a parameter - `cyc_now_ms()` is the convenience wrapper -
which is why the tests run a full expiry cycle without waiting for a real second
to pass. `cyc_now_ms()` reads a monotonic clock, so a wall-clock jump can never
expire a handshake or kill a live peer.

### Events

| `cyc_event.kind` | Raised when |
|---|---|
| `CYC_EVENT_CONNECTED` | the first tick, always, even on UDP where nothing "connects" |
| `CYC_EVENT_READY` | verdict 0 arrived (client) or was sent (server). Only now may the application send |
| `CYC_EVENT_HANDSHAKE_FAILED` | verdict 1/2/3, a broken handshake payload, or the deadline. `reason` is a `cyc_handshake_failure` |
| `CYC_EVENT_MESSAGE` | a DATA frame while ready; `message_id`, `payload`, `payload_len` |
| `CYC_EVENT_PROBE` / `CYC_EVENT_ACK` | a PROBE or ACK frame while ready |
| `CYC_EVENT_DISCONNECTED` | the transport closed or broke, or the peer stopped answering. `reason` is a `cyc_disconnect` |

**Exactly one terminal event per session.** If a handshake failed, no
`CYC_EVENT_DISCONNECTED` follows it, even if the transport dies a moment later.

Server events carry `peer`; client events leave it `0`.

Sending is refused, never queued, in four cases: `CYC_ERR_NOT_READY` before the
verdict, `CYC_ERR_CONGESTED` while a frame is still stuck, `CYC_ERR_TOO_LARGE`
when the payload is over `max_message_bytes` or the transport cannot carry it,
and `CYC_ERR_CLOSED` once the session is over. `CYC_ERR_TOO_LARGE` does **not**
kill the session, and the frame is not retried.

## Writing a transport

A transport moves bytes and reports what happened, immediately. It never blocks,
never spawns a thread, never calls back into the runtime, never interprets a
byte, and never adds a header of its own.

```c
typedef struct cyc_transport_vtable {
    cyc_transport_kind (*kind)(const cyc_transport *transport);
    cyc_send_result (*send)(cyc_transport *transport, const uint8_t *bytes, size_t len,
                            size_t *accepted);
    cyc_recv_result (*recv)(cyc_transport *transport, uint8_t *buffer, size_t cap,
                            size_t *received, size_t *needed);
    void (*close_soft)(cyc_transport *transport);
    void (*close_hard)(cyc_transport *transport);
} cyc_transport_vtable;
```

| Outcome | Guide symbol | Meaning |
|---|---|---|
| `CYC_SEND_SENT` | ok | every byte was taken |
| `CYC_SEND_WOULD_BLOCK` | wait | **no** byte was taken; ask again next tick |
| `CYC_SEND_TOO_LARGE` | refuse | this frame will never fit. Do not retry, do not kill the session |
| `CYC_SEND_CLOSED` / `CYC_SEND_ERROR` | closed / broken | the peer closed cleanly / the link broke |
| `CYC_RECV_RECEIVED` | ok | a stream may return any number of bytes; a packet transport must return exactly one whole frame |
| `CYC_RECV_WOULD_BLOCK` | wait | nothing to hand over yet |
| `CYC_RECV_NEED_CAPACITY` | grow | the buffer is too small; set `*needed` and **keep the packet**, the runtime grows and asks again in the same tick |
| `CYC_RECV_CLOSED` / `CYC_RECV_ERROR` | closed / broken | as above |

Return `CYC_TRANSPORT_STREAM` from `kind` and the runtime inserts its own framing
layer; return `CYC_TRANSPORT_MESSAGE` and you are promising one whole frame per
`recv`, never half of one. If the transport distinguishes text from binary
payloads, always choose binary - a Cyclone frame is not valid UTF-8.

`CYC_SEND_PARTIAL` is the one addition this library makes to that vocabulary, and
it is what the guide's "declare yourself a byte stream and let the core deal with
it" means in practice: a stream transport that accepted the first `*accepted`
bytes says so, and the runtime finishes the rest at the top of the next tick,
before any other frame goes out. A packet transport must never return it.

The other place this library is explicit: a control frame produced while a frame
is already stuck is appended behind it rather than dropped or overtaking it. Wire
order is absolute, and control frames are rare and tiny. Application sends are
still refused with `CYC_ERR_CONGESTED`, so nothing queues without bound.

`close_hard` is called exactly once, by `cyc_connection_destroy` or when the
server drops a finished peer, and it must free the transport's own state.

Built in: `cyc_tcp_connect` / `cyc_tcp_listen` (stream) and `cyc_udp_connect` /
`cyc_udp_listen` (message). Both non-blocking, both on plain BSD sockets or
Winsock. WebSocket, TLS and QUIC are out of scope for this library and need no
change here to be written beside it.

## Limits

| Quantity | Cap | Source |
|---|---|---|
| one message payload | `max_message_bytes`, 65536 by default | configuration; the protocol's own ceiling is 16 MiB |
| one HANDSHAKE payload | 1 MiB | allocation guard |
| messages declared in a hello | 1 000 000 | checked before any multiplication, so a hostile count cannot overflow |
| query rounds per session | 1 | |
| frames processed per tick | `max_frames_per_tick`, 64 | tick fairness |
| UDP datagram | 65 507 B | over that, `send` answers `CYC_SEND_TOO_LARGE` |
| UDP peers tracked by one listener | 256 | per-address queues in the hub |
| datagrams queued per UDP peer | 64 | oldest dropped first, which is what UDP means |

## What the tests prove

`make test` runs 60 checks, and `make sanitize` runs every one of them again
under AddressSanitizer and UndefinedBehaviorSanitizer:

- `tests/test_frame.c` - byte-for-byte frame layout, a stream fed one byte at a
  time, several frames in one read, permanent poisoning, packet framing, the caps
- `tests/test_handshake.c` - all four decision branches, both query outcomes,
  every malformed hello/query/verdict/reply shape, the client deadline across two
  rounds, and a server that never times out a peer answering probes
- `tests/test_heartbeat.c` - a full expiry cycle without waiting for real time
- `tests/test_runtime.c` - a fake transport: congestion, partial writes,
  `NEED_CAPACITY`, `TOO_LARGE`, the tick budget, one terminal event
- `tests/test_interop.c` - real TCP and UDP sockets, both directions, including a
  handshake that needs the second round
- `tests/test_demo.c` - a `cyclonec`-generated codec carried over a real socket,
  model in and model out

Two of those handshake cases carry RFC-0003 §8.6 up into this layer: a peer that
appended a field at the end, and a peer that dropped one from the end, both
connect. V-001 and V-002 say those peers MUST NOT be rejected, and a handshake
that refused them would break the guarantee the codec below it keeps.

RFC-0003's own vectors test a codec, and the codec is `cyclonec`'s - so that
suite lives there, run against the generated code that actually ships.

## What this library does not do

No reordering, no retransmission, no deduplication, no encryption, no
compression, no checksums. Over TCP you inherit ordering and integrity from the
transport; over UDP packets may be lost, reordered or duplicated and are handed
up exactly as they arrived. Heartbeat and dead-peer detection work identically on
both, because they run on a clock rather than on sequence numbers.

Reconnection is the application's decision. A transport that quietly reconnects
itself would leave the two ends disagreeing about whether the session is alive.

WebSocket is out of scope, deliberately and permanently - no transport, no
placeholder, no extension point.

## Layout

```
include/cyclone.h         the three annotation markers cyclonec reads
include/cyclone/          the public API, one header per concern
src/frame.c               frame envelope, packet decode, incremental stream decoder
src/schema.c              the schema table a handshake compares
src/handshake.c           hello, verdict, query, reply, and the server's decision
src/session.c             the transport-agnostic state machine and its clocks
src/core.c                the tick loop binding a session to a transport, and the event arena
src/connection.c          one session
src/server.c              many sessions, one listener
src/transport/            the socket glue, TCP and UDP
examples/demo/            one annotated model, and the tree cyclonec wrote from it
```

`src/session.c` knows nothing about sockets: frames in, frames and events out,
and every timestamp passed from outside. That is what makes the whole expiry
behaviour testable, and it is why the transports are as small as they are.
